# DeckProbe 2.5.0 字段能力说明

## 口径

本文档不以 README 的宣称作为最终依据，而是同时使用三层证据：

1. DeckProbe 2.5.0 二进制的 `targets <profile>` 实时目标清单；
2. 对数据集中每个文件执行 `--probe-level deep --targets @all --view values`；
3. 对 DeckProbe 没有目标字段的 OOXML 特征，直接检查 ZIP 包内 XML，仅用于证明“文件中确实有此特征”，不冒充 DeckProbe 输出。

`deep + @all` 是当前最完整探测口径。`deep` 是有序层级 `header < metadata < deep` 的最高层，`@all` 会选择当前 profile 中 `min_level <= deep` 的全部适用 target，所以结果包含 header、metadata 和 deep 三层。返回 `status: partial` 通常只表示某些可选元数据在该文件中不存在，不等于整个探测失败。

本说明覆盖 DeckProbe 2.5.0 live discovery 得到的全部 **124 个唯一 target ID**。机器可读的 profile 适用性、最小层级和值 Schema 见 `DeckProbe字段目录.json`；`excel.comment_*` 等通配写法只用于说明“没有这一类 target”，不属于 target ID。

探测层级：

- `header`：文件头、容器与类型身份。
- `metadata`：元数据和有界的结构统计。
- `deep`：解压、对象遍历或 IWA 解码后才能得到的字段。

## 通用文档字段

| 字段 | 层级 | 类型 | 含义 |
|---|---|---|---|
| `document.format` | header | string | 验证后的文档家族，如 `pdf`、`office-open-xml`、`iwork`。 |
| `document.format_profile` | header | string | 具体格式配置，如 `pdf`、`docx`、`xlsx`、`pptx`、`keynote`。 |
| `document.mime_type` | header | string | 结合容器和内部主部件验证得到的 MIME，不是只看扩展名。 |
| `document.file_size` | header | u64 | 物理文件大小，字节。 |
| `document.extension` | header | string | 规范化后的输入扩展名。 |
| `document.extension_matches` | header | bool | 扩展名是否与实际检测到的文档类型一致。 |
| `document.title` | metadata | string/null | 文档声明的标题。 |
| `document.subject` | metadata | string/null | 文档主题。 |
| `document.author` | metadata | string/null | 创建者/作者。 |
| `document.keywords` | metadata | string/null | 关键词。 |
| `document.description` | metadata | string/null | 描述或备注。 |
| `document.created_at` | metadata | string/null | 声明的创建时间。 |
| `document.modified_at` | metadata | string/null | 声明的修改时间。 |
| `document.application` | metadata | string/null | 生成或保存文档的应用名。 |
| `document.application_version` | metadata | string/null | 生成应用版本。 |
| `document.language` | metadata | string/null | 声明的语言；当前主要适用于现代 iWork。 |
| `document.locale` | metadata | string/null | 声明的地区设置；当前主要适用于现代 iWork。 |

适用性并不完全相同：现代 OOXML 和 PDF 提供的通用元数据最多；现代 iWork 主要提供应用、版本、语言和地区；旧版 CFB Office 不提供 `description`、`application_version`、`language`、`locale`。

## 安全与主动内容

| 字段 | 层级 | 含义与边界 |
|---|---|---|
| `security.encrypted` | header/metadata | 检测到容器或内容加密。 |
| `security.password_protected` | metadata | 是否需要非空密码才能读取受保护内容；不能确定时可为 `null`。 |
| `security.has_macros` | metadata | 包内是否存在 Office VBA 宏项目。 |
| `security.has_digital_signature` | metadata | 是否存在数字签名结构；不表示证书可信或签名有效。 |
| `security.signature_count` | deep | 签名结构数量；同样不做密码学有效性验证。 |
| `security.has_javascript` | deep | 检测到嵌入的主动 JavaScript。当前 PDF 有可验证正例；OOXML 文件中常为 unresolved。 |
| `security.has_external_relationships` | metadata | PDF 行为/注释或 OOXML relationship 指向包外部资源。这是包级判断，不返回每条 URL。 |
| `security.has_embedded_files` | metadata | 文档中存在附件、嵌入包或 OLE/对象部件。 |
| `security.active_content_risk` | deep | 规则化风险级别：`none/low/medium/high/unknown`；不是恶意代码鉴定。 |
| `quality.corrupted` | deep | 结构验证是否发现损坏；当前主要适用于现代 iWork，`null` 表示未完整验证。 |

## 当前明确不返回的内容级字段

下列特征在本数据集中都有真实样本，但 DeckProbe 2.5.0 没有对应 target，或已有 target 但样本证明存在漏报：

| 特征 | 当前状态 | 证据 |
|---|---|---|
| Word 页眉/页脚 | 无专用字段 | `Word_职称评审表_22页多页眉页脚.docx` 包内有多组 header/footer 部件及关系。 |
| Word 超链接条数和 URL | 无专用字段 | 只能通过 `security.has_external_relationships` 知道存在外链。 |
| Word 图表数 | 无专用字段 | 即使 DOCX 含 chart part，也不返回 Word chart count。 |
| Excel 公式数/公式文本 | 无专用字段 | OCB NBA 工作簿有 12,844 个公式；Numbers 的公式定义数是另一个格式特定能力。 |
| Excel 合并单元格数/范围 | 无专用字段 | SpreadsheetBench 月度汇总工作簿有 605 个合并单元格结构。 |
| Excel 隐藏行/隐藏列 | 无专用字段 | `excel.hidden_sheet_count` 只统计隐藏工作表，不是行列。Numbers 有独立行列字段。 |
| Excel 表的行列尺寸、默认行高/列宽 | 无专用字段 | Numbers 的 `table_dimensions` 有，Excel 没有。 |
| Excel 页眉/页脚 | 无专用字段 | OCB NBA 工作簿 XML 有 `<headerFooter>` 定义。 |
| Excel 批注数 | 无专用字段 | 当前没有 `excel.comment_*` target。 |
| PowerPoint 表格数/行列数 | 无专用字段 | 高速成型线业务演示文稿有 9 个 `<a:tbl>` 结构。 |
| PowerPoint 动画数/类型/时序 | 无专用字段 | 可穿戴 PPG 路线图有 24 个 `<p:timing>` 时间树，但报告不暴露动画目标。 |
| PowerPoint 切换数/类型/时长 | 无专用字段 | 可穿戴 PPG 路线图有 48 个 transition 结构。 |
| PowerPoint OMML 公式 | 无专用字段 | 统计学课程演示文稿有 64 个 OMML 公式结构。 |
| PowerPoint 页眉/页脚/日期/页码占位符 | 无专用字段 | 综合元素演示文稿包内存在 footer/date/slide-number 类占位符。 |
| PowerPoint 隐藏幻灯片的 `p:sld@show=0` 写法 | 已有字段但实测漏报 | 哥斯达黎加交通模型有 2 个 `show="0"`，`powerpoint.hidden_slide_count` 仍返回 0。 |
| Keynote 现代 Build effects | 已有字段但实测漏报 | Cupertino Files 的 Keynote 26.3 真实样本含 3 种 Build In，`slides_with_builds_count` 返回 0。 |
| Numbers 已启用过滤规则 | 已有字段但实测漏报 | 样本含两条已启用规则，`filtered_row_count` 返回 0。该字段当前看的是持久化 row-state，不等于规则存在。 |
| Pages/Word/Excel/PPT 页眉页脚具体文本 | 无专用字段 | Pages 样本有每章节的非空页眉页脚，DeckProbe 只返回章节统计。 |

## 解读时最容易误会的点

- `*_part_count` 是包内唯一 XML part 数，不必然等于用户看到的逻辑对象数。
- `unique_*_asset_count` 是去重后的资产部件数，同一图片被引用十次仍可能只计 1。
- `word.page_count` 和 `pages.cached_page_count` 都是持久化统计，不是 DeckProbe 自行排版后得到的精确当前页数。
- `security.has_digital_signature=true` 只证明签名结构存在，不证明签名未被篡改、证书未过期或信任链可信。
- `status: partial` 必须结合 `unresolved_targets` 解读；不能把字段缺失当成值为 0 或 `false`。
- 字段能力与扩展名路由能力不是同一件事。例如 XLSB 在格式清单中是“identity only”，不能推导出它拥有 XLSX 的全部深字段。

具体样本、实测值和盲区对照见 [深字段覆盖矩阵.md](./深字段覆盖矩阵.md)。
